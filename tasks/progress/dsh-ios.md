## Later additions (same session)

- **Player landed.** `Cinemacore/Player/PlayerModel.swift` + `PlayerScreen.swift` (real AVPlayer:
  header-fields key, `.playback` audio session, overlay controls, ±10 s, auto-hide, explicit
  fullscreen, the six `SelectionSheet` panels, caption overlay, silent resume, 5 s progress writes,
  auto-advance). Caption parsing lives in Core (`SubtitleCues.swift`) so it is Linux-tested.
- **Signing contract is now shared, not duplicated.** `contracts/signing-vectors.json` is the single
  source of truth and BOTH suites load it: `core/sign/sign_test.go` and
  `CinemacoreCore/Tests/.../SigningVectorFixture.swift`. It carries the client-token, TR-signature,
  gslb and password vectors plus **53 `resourceVectors` cases generated from the Go reference**.
- **`Signing.resource()` was rewritten** to parse by hand. Foundation's `URLComponents` normalises a
  stray `%` to `%25` and re-encodes paths, while Go leaves `RawQuery` raw and fails the whole parse on
  a bad path escape. The shared vectors pin the agreement. Known limit: a query value that decodes to
  *invalid* UTF-8 (e.g. `%FF`) is representable in a Go string but not a Swift `String`; excluded from
  the vectors and documented in `Signing.swift` rather than pretended. App-generated URLs are valid UTF-8.
- **Resume key bug fixed.** `PlaybackRequest.historyID` used `"<id>_S<n>_E<n>"` while `ResumePoint.id`
  used `"<id>-s<n>e<n>"`, so lookups always missed and resume was silently dead. Both now call
  `ResumePoint.makeID(subjectID:season:episode:)` — one definition.

## Live gateway verified (same session, later)

The Go side landed while this session ran, so the live path was exercised for real:

```
curl localhost:8080/health                 -> {"status":"ok"}
curl localhost:8080/version                -> {"version":"0.1.0"}
curl localhost:8080/v1/home                -> 200, real rails (pbcdn.aoneroom.com posters, ratings, genres)
curl 'localhost:8080/v1/search?q=dune'     -> 200, real results
curl localhost:8080/v1/detail/<id>/seasons -> 200, real episode tree
curl 'localhost:8080/v1/play?subjectId=<id>&season=1&episode=1'
      -> {"streams":[{"quality":"1080","url":"https://macdn.aoneroom.com/.../x.mp4"}, ...],"subtitles":[]}
```

Consequences recorded in the README:

- **The HLS-vs-MP4 question is settled: progressive MP4.** Offline should use a `URLSession` download with
  the rendition's headers, not `AVAssetDownloadURLSession`.
- **Rendition labels carry no suffix** — live data sends `"1080"/"720"/"480"`, not `"1080p"`. The rank
  parser already handled both; a test now pins it.
- **`Subject.kind` is `"series"` live, not the contract's `"2"`.** 7 of 13 sampled series had
  `seasonCount: 1`, so the old `isSeries` (kind=="2" || "tv" || seasonCount>1) called them movies and the
  detail screen would have hidden the episode tree. `isSeries` now accepts `"2"/"tv"/"series"/"show"` and
  treats `"1"/"movie"/"film"` as a movie, falling back to `seasonCount` only for an unknown kind.
  Two tests added. Core suite is now 162 tests / 27 suites.
- Live episodes arrive with **no `title` and no `duration`**, which is exactly what the tolerant decoders
  in `Models+Decoding.swift` were added for — without them the season tree would not have decoded at all.
- On a physical iPhone the default `127.0.0.1:8080` gateway is the *phone*, so the LAN address must be set
  in Settings → Gateway URL. Documented in the README.
