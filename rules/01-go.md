# 01 — Go

Scope: `core/`, `server/`, `cmd/`. Source: Effective Go, Go Code Review Comments, Uber Go Style, Google Go Style.

## Style
- `gofmt`/`goimports` — no exceptions. Tabs, no alignment-by-hand.
- Short names for short scopes; `ctx`, `err`, `i`. Descriptive for exported/package scope.
- Package names: lowercase, single word, no stutter (`sign.ClientToken`, not `sign.SignClientToken`).
- Comments: full sentences on **exported** identifiers, starting with the name. None inside functions unless the *why* is non-obvious.

## Errors
- Wrap with context: `fmt.Errorf("sign ticket for %s: %w", id, err)`.
- Return errors up; handle at the boundary that can act. Never `_ = err` silently.
- `errors.Is`/`errors.As` for inspection; sentinel or typed errors, not string matching.
- `panic` only for programmer error at init (e.g. invalid constant), never for input.

## APIs
- Accept interfaces, return concrete structs.
- `context.Context` is the **first** parameter, never stored in a struct.
- Functional options for constructors with >3 optional settings.
- No package-level mutable global state. Dependencies are injected.
- Interfaces are declared at the **consumer**, small (1–3 methods).

## Concurrency
- Every goroutine has a clear owner and exit. Prefer `errgroup` for fan-out with cancellation.
- Always check `ctx.Err()` in loops; honour cancellation.
- Protect shared state with a mutex; document what it guards.

## Layout (this repo)
- `core/` = pure, testable, no `net/http`. `server/` = transport only. `cmd/` = wiring.
- One primary type per file, named after the file.

## Testing
- Table-driven, subtests, `t.Run`. `-race` in CI. See `06-testing.md`.

## Banned
- `init()` with side effects · mutable globals · `interface{}`/`any` in public APIs · hand-rolled HTTP framing · `time.Sleep` in tests.
